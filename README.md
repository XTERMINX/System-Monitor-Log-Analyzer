# System Monitor & Log Analyzer

Консольное приложение для анализа логов серверов и мониторинга инфраструктуры.

## О проекте

Программа читает лог-файлы серверов, разбирает их, анализирует нагрузку,
ищет ошибки и аномалии, формирует отчёты. Работает с локальными файлами,
без внешних API и без базы данных.

Разработано по техническому заданию, разбито на модули.

## Возможности

- Генерация тестовых данных (серверы и логи)
- Чтение логов построчно через генераторы (без загрузки в память)
- Разбор строк в структурированные записи
- Фильтрация и поиск по уровню, серверу, дате, тексту
- Статистика по CPU, RAM, диску и сети (NumPy)
- Анализ данных через Pandas: группировки, сортировки, сводки
- Поиск аномалий по каждому серверу отдельно
- Формирование отчётов (JSON, CSV, TXT)
- Параллельная обработка: потоки, процессы, asyncio
- Сравнение производительности (Benchmark)
- Полноценное логирование работы приложения

## Технологии

- Python 3.x
- NumPy — численные расчёты
- Pandas — анализ и агрегация данных
- asyncio — асинхронная обработка
- threading — многопоточность
- multiprocessing — многопроцессорность
- logging — журнал работы приложения
- itertools, functools — вспомогательные инструменты

## Установка

1. Установить Python 3.10 или выше.
2. Установить зависимости:
## python main.py

### Разделы меню

**1. Servers** — просмотр списка серверов.

**2. Logs** — работа с логами:
- все записи
- только ERROR / CRITICAL / WARNING
- поиск по сообщению, серверу, дате

**3. Analyze** — анализ логов:
- количество записей по уровням
- проблемные серверы (топ по ERROR)
- сводная таблица по серверам

**4. Statistics** — статистика нагрузки (NumPy):
- среднее, минимум, максимум, медиана, отклонение
- по CPU, RAM, диску, сети

**5. Anomalies** — поиск аномалий:
- по каждому серверу отдельно
- порог: среднее ± 1.5 × отклонение

**6. Reports** — формирование отчётов в папку `reports/`.

**7. Generate test servers** — создание серверов.

**8. Generate test logs** — создание лог-файлов.

**9. Benchmark** — сравнение производительности:
- последовательно
- потоки
- asyncio
- multiprocessing

**0. Exit** — выход.

## Логирование

Журнал работы ведётся в `logs/application.log`.
Используется `TimedRotatingFileHandler` — ротация каждый день в полночь,
хранятся последние 7 файлов.

## Аномалии

Аномалия — значение, вышедшее за пределы `среднее ± 1.5 × отклонение`.
Считается по каждому серверу отдельно, потому что у разных серверов
разная норма. Порог настраивается в `data/settings.json`.

## Итоговый тест

Программа проверена на наборе:

- 100 серверов
- 500 лог-файлов
- 1 000 000 записей

Все этапы (генерация, парсинг, анализ, отчёты, benchmark) проходят успешно.

## Архитектура

Проект разбит на модули:

- **data** — данные и настройки
- **modules** — логика приложения
- **utils** — вспомогательные функции

Каждый модуль отвечает за свою задачу. Код не в одном файле,
легко поддерживать и расширять.
